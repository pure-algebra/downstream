### L4 — exact fail-closed axiom audit

For environment `E` imported by `Hash.Sha3.Verified`:

```text
K = {axiomInfo, defnInfo, thmInfo, opaqueInfo, quotInfo,
     inductInfo, ctorInfo, recInfo}
covered(E) = { d | module(rawName(d)) has prefix Hash.Sha3
                    and module(rawName(d)) != Hash.Sha3.Audit
                    and not isInternal(privateToUserName(rawName(d))) }
covered_k(E) = { d in covered(E) | Kind_B(d) = k }  for every k in K
covered(E) = disjointUnion { covered_k(E) | k in K }
M = 9
N = |covered(E)| = sum { |covered_k(E)| | k in K } >= 70
O = union { collectAxioms(E,d) - A | d in covered(E) }
A = {propext, Classical.choice, Quot.sound}

O != {}  => #sha3_axiom_audit throws and lists O
O = {}   => emittedMessages = [
  "sha3 axiom audit: <fresh N> declarations across 9 modules; allowlist " ++
  "[propext, Classical.choice, Quot.sound]; 0 offenders"
]
```

Every member of `env.constants` that survives the module/internal-name
projection is counted once and passed to `Lean.collectAxioms`, independent of
its `ConstantInfo` constructor. In particular, an `.axiomInfo` declaration is
itself an axiom dependency and must be rejected even when unused; an
`.opaqueInfo` declaration must have its transitive dependencies collected.
The remaining six constructors are counted and collected by the same uniform
path. No constructor may fall through or be silently ignored. The preferred
source shape is `for (n₀, _) in env.constants.toList`; a kind match that gates
counting or collection violates this law.

Module attribution is performed on each raw environment name before
`privateToUserName` normalization; collection also uses the raw name, while
diagnostics display the normalized name. The independent breaker probe freshly
measures the current production partition as:

```text
total=379; modules=9;
axiom=0; defn=68; thm=311; opaque=0; quot=0; induct=0; ctor=0; rec=0
```

Thus the current `Hash.Sha3.Verified` success pin is exactly 379 declarations across
9 modules. Any subsequent source change must freshly remeasure all eight
counts, prove their sum is `N`, and deliberately update the one-line pin.
Mutation probes use different import closures and must throw before emitting a
success line; they never change the production 379/9 pin. A widened allowlist,
an empty/partial/kind-filtered scan, a silent offender, a second message, or
order drift is a failure.

## Explicit error states

- **E1 evidence leakage:** `I(Hash.Sha3)` reaches `Hash.Sha3.Kats` or
  `Hash.Sha3.KeccakProbe`, `Hash.Sha3.BridgeEvidence`, `Hash.Sha3.Audit`, or `Hash.Sha3.Verified`.
- **E2 amputated API:** evidence imports disappear only because a required API
  module was also dropped.
- **E3 signature drift:** any frozen Roundtrips proposition or
  `Hash.Sha3.Bridge.sha3_ne_prefips_spec` changes while proof/module ownership is
  retargeted.
- **E3a generic-helper drift:** an explicit binder restricts a formerly
  universe-polymorphic helper (for example `{α : Type}`), identifies `u₁` and
  `u₂`, changes binder visibility/order, or changes the resulting proposition.
- **E4 frozen-byte drift:** either Spec or Impl SHA-256 changes.
- **E5 mass reduction retained:** either private helper still uses a decision
  procedure over the finite carrier.
- **E6 cost miss:** fresh direct Roundtrips elaboration is nonzero or takes at
  least 5000 ms on the acceptance host.
- **E7 audit fail-open:** an out-of-allowlist axiom produces success, including
  an unused `.axiomInfo` declaration or an axiom reachable only through an
  `.opaqueInfo` declaration.
- **E8 audit undercoverage:** a module count other than 9, an unpinned fresh
  declaration count, fewer than 70 declarations, the wrong module projection,
  normalizing a private name before module attribution, omitting any of the
  eight `ConstantInfo` constructors, or a per-kind sum unequal to `N` inflates
  or empties coverage.
- **E9 verdict drift:** allowlist/order/count/message differs from the one
  `#guard_msgs` pin, or success emits more than one message.
- **E10 print residue:** any `#print axioms` command survives.
- **E11 metadata/task drift:** the default/test roots or canonical commands do
  not name the intended projections.
- **E12 stale/wrong recheck:** `leanchecker` is not run fresh against
  `Hash.Sha3.Verified`, or its exit/output shape is not recorded.
- **E13 overclaim:** sampled KATs, measured timing, kernel elaboration, or an
  undated/unreceipted dual-architecture replay is reported as a stronger or
  current implementation/security result.
- **E14 report elision:** any executable command is absent, grouped, described
  instead of quoted verbatim, reordered, or missing its working-directory/log
  disposition.

## Degenerate and satisfiability probes

The battery executes its predicate self-probes before inspecting the tree.

- **Degenerate root:** `import Hash.Sha3.Spec` excludes evidence but fails because
  the other five required API modules are absent.
- **Delete-the-file cheat:** an empty Roundtrips source contains no `decide`,
  but the Lake build and exact signature probe fail.
- **Constant verdict cheat:** an Audit text containing the success sentence but
  no `Lean.collectAxioms`, module projection, offender throw, or `N < 70` guard
  fails the audit-shape probe.
- **Definition/theorem-only cheat:** matching only `.defnInfo | .thmInfo` fails
  the static all-constructor shape and both preserved mutation attacks.
- **Unused-axiom cheat:** `attacks/S0-audit/Hash/Sha3/AxiomMutation.lean` imports the
  real API closure and adds an unused Hash.Sha3 axiom; success is a fail-open witness.
- **Opaque-dependency cheat:** the opaque mutation depends on an axiom from a
  non-Hash.Sha3 module, so direct axiom scanning cannot mask an omitted opaque path.
- **Count-partition probe:** `s0/AuditCoverageProbe.lean` independently counts
  all eight constructors; their sum and module count must equal the exact
  `#guard_msgs` pin.
- **Empty scan cheat:** `N = 0` cannot satisfy `N >= 70`.
- **Metadata-only cheat:** correct strings outside the named Lake/task tables do
  not satisfy the section/target checks.
- **Satisfiability fixture:** the exact S0 root set, Lake metadata, task commands,
  nine-module audit command shape, evidence-split import graph, and a structural
  proof placeholder satisfy the static predicates simultaneously.
- **Live positive controls:** the current frozen hashes and seven public
  propositions must pass even while the S0 obligations are red. Thus the packet
  does not contradict the retained baseline.
- **Claim-scope controls:** removing the dual-host clause passes; retaining it
  requires a dated recorded/measured receipt paragraph. Grouping read-only
  commands or polls cannot satisfy the report ledger.
